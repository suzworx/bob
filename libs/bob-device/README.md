# bob-device

Bob's portable device core: the board-independent half of the Waveshare round UI, as a PlatformIO library inside the
repo. [ADR 0004](../../docs/adr/0004-bob-device-platform.md) phase P1 (#1076). Every file here is plain C++17 with no
Arduino, M5 or ESP-IDF include, so the same sources build for the ESP32 firmware, the desktop simulator and the host
tests.

## What is here (`src/`)

| Piece | Files |
| --- | --- |
| Design tokens (generated by `node design/bob/build.mjs`) | `bob_tokens.h` |
| Emotion table: the X-macro, poses, eyes, gestures, accents, palette, frame geometry | `bob_emotion_table.h` |
| Move and idle tables, springs, the "alive" maths | `bob_moves.h`, `bob_demo_moves.h`, `bob_life.h` |
| Rig: part tables (generated by `scripts/bob_rig_header.py`), kinematics, rasteriser, eyes | `bob_rig_data.h`, `bob_rig.h`, `bob_raster.h`, `bob_face_aa.h` |
| Rig compositor: parts into a `bob::Framebuffer`, built with `BOB_RIG` | `bob_rig.cpp`, `bob_rig_blobs.inc` |
| Ring light: the ring-language table, the mood policy, the per-degree composer | `round_ring_spec.h`, `round_ring_policy.h`, `round_ring_compose.h` |
| Scenes: the catalogue and the per-layer clocks and keyframes | `scene_table.h`, `scene_layers.h` |
| Board seam | `bob_hal.h` |

What stays in `apps/cardputer`: everything that draws through LovyanGFX/M5GFX or reads hardware (the round UI, the
face and accents, `bob_motion.cpp`, the ring renderer `round_ring.cpp`, the scene compositor `scene_engine.cpp`,
touch), the device halves of the split headers (`bob_emotions.h`, `bob_art.h`, `scene_engine.h`), and the art the
compositor embeds (`apps/cardputer/lib/bob_art/rig/*.rgb565a8`, found through the build's `-Wa,-I` path).

## The board seam

`bob_hal.h` describes a board the way the Muse gadget SDK does: one `bob::Board` with the display geometry, a few
capability flags and the operations (framebuffer, dirty rect and present, touch point, talk button, mic and speaker
levels, clock, memory). A null operation means the board lacks the feature. Each target defines `bob::hal()` once:

| Target | Definition |
| --- | --- |
| Waveshare ESP32-S3-Touch-LCD-1.85C and the Cardputer | `apps/cardputer/src/bob_board.cpp` (one board per build) |
| Desktop simulator | `tools/bob-sim/src/stubs.cpp` |

Today the core calls `alloc` (the rig's caches and scratch) and draws into the `bob::Framebuffer` it is handed. The
other operations are filled with the firmware's existing functions and are what P2 moves the round UI, the ring and
the scene engine onto.

## Consumers

- Firmware: `apps/cardputer/platformio.ini` links it with `symlink://../../libs/bob-device` (every product env, and
  the bring-up env). Never copy it into `.pio`.
- Simulator and visual gate: `tools/bob-sim/CMakeLists.txt` adds `src/` to the include path and compiles
  `bob_rig.cpp` (the path is found from the firmware path, so the gate's relocated copy finds it too).
- Host tests: `apps/cardputer/test/host/run.mjs` adds `-I../../libs/bob-device/src`; the suites stay in
  `apps/cardputer/test/host/` (`test_bob_rig`, `test_bob_life`, `test_bob_face_aa`, `test_round_ring_*`, `test_scene`).

A change here counts as a firmware change: `scripts/hil/firmware-hash.mjs` hashes `libs/bob-device/`, and the visual
gate requires a pass for `libs/bob-device/src/` (`tools/visual-gate/flash-guard.mjs`). The `cardputer-ui` domain owns it
(`.claude/domains.json`).

## Rules

- No Arduino, M5, ESP-IDF or board macros here. A new board-specific need becomes a `bob::Board` operation.
- Generated files (`bob_tokens.h`, `bob_rig_data.h`, `bob_rig_blobs.inc`) are changed through their generators only.
- Rendering stays byte-identical across a refactor: render the gate cases before and after
  (`node tools/visual-gate/candidate.mjs --out <dir> [--fw <checkout>] --rig on`) and compare the PNGs.
